### Impediment Resolution Framework

#### Impediment Categories

| Category | Examples | Resolution Path |
|----------|---------|----------------|
| Technical | Build failures, environment issues | DevOps, engineering |
| Process | Unclear requirements, approval delays | PO, stakeholders |
| Organizational | Resource conflicts, policy blockers | Management, HR |
| External | Vendor delays, API issues | Procurement, vendor mgmt |
| Interpersonal | Team conflict, communication gaps | Coaching, mediation |

#### Resolution Process

1. **Identify**: Surface impediments in daily standup
2. **Classify**: Categorize by type and urgency
3. **Assign**: Scrum Master owns resolution or delegates
4. **Track**: Maintain impediment board with status
5. **Resolve**: Take action, escalate if needed
6. **Prevent**: Address root cause to prevent recurrence

#### Escalation Path

- **Level 1**: Team self-resolves (target: same day)
- **Level 2**: Scrum Master facilitates (target: 1-2 days)
- **Level 3**: Management involvement (target: 1 week)
- **Level 4**: Organizational change required (target: sprint)

## Common Pitfalls and How to Avoid Them

| Pitfall | Why It Happens | How to Avoid |
|---------|---------------|---------------|
| Analysis paralysis | Too much data, not enough action | Set decision deadlines, use frameworks |
| Premature scaling | Scaling before validating | Prove ROI at small scale first |
| Ignoring data | Relying on gut feelings | Build data review into process |
| Tool overload | Adding tools without strategy | Audit tool stack quarterly |
| Siloed execution | Teams working independently | Regular cross-functional syncs |
| Inconsistent measurement | Different teams, different metrics | Standardize KPI definitions |
| Set-and-forget | Launching without ongoing optimization | Schedule regular optimization reviews |
