# Data Presentation Techniques

Structure and deliver data presentations that persuade and drive action.

---

## Narrative Structures

### The Situation-Complication-Resolution (SCR) Framework

| Phase | Purpose | Content |
|-------|---------|---------|
| Situation | Set context | Current state, background data |
| Complication | Create tension | Problem, gap, or opportunity identified |
| Resolution | Drive action | Recommended solution with supporting data |

### The McKinsey Pyramid Principle

Start with the answer, then support with evidence:
1. **Governing thought**: "We should invest $2M in customer retention"
2. **Key arguments**: Grouped logically (3-5 supporting points)
3. **Supporting data**: Charts and analysis backing each argument

### The Before-After-Bridge

1. **Before**: Here's the current state (pain points, metrics)
2. **After**: Here's where we could be (target metrics, vision)
3. **Bridge**: Here's how to get there (specific recommendations)

## Slide Design for Data

### The One-Slide-One-Message Rule

Each slide should communicate exactly one insight:
- **Title**: The insight/takeaway (not a description)
  - Bad: "Q3 Revenue by Region"
  - Good: "APAC Revenue Grew 45%, Offsetting NA Decline"
- **Visual**: One chart supporting the title
- **Annotation**: Highlight the specific data driving the insight
- **Source**: Data source and date at bottom

### Chart Selection for Slides

| Slide Purpose | Best Chart | Notes |
|---------------|-----------|-------|
| Show a trend | Line chart | Clean, no more than 3-4 series |
| Compare categories | Horizontal bar | Sorted by value |
| Show composition | Stacked bar or waterfall | Limit to 5-6 segments |
| Highlight a number | Large KPI with context | "+23% vs. last quarter" |
| Show correlation | Scatter with annotations | Highlight key data points |

## Audience Adaptation

### Executive Audience
- Lead with recommendations and business impact
- Use 3-5 slides maximum for key decisions
- Include financial context (revenue, cost, ROI)
- Prepare backup detail slides (appendix)
- Present in 10-15 minutes, leave time for discussion

### Technical Audience
- Include methodology and data sources
- Show confidence intervals and limitations
- Present alternative analyses considered
- Be prepared for deep technical questions
- Allow 20-30 minutes for presentation + Q&A

### Cross-Functional Audience
- Define all terminology and acronyms
- Use analogies to bridge domain knowledge gaps
- Focus on shared goals and metrics
- Visualize complex concepts simply
- Keep to 15-20 minutes with clear takeaways

## Delivery Best Practices

### Verbal Techniques
- **State the insight first**: "Customer churn increased 15% — here's why"
- **Walk through the chart**: Explain axes, then the pattern, then the implication
- **Use silence**: Pause after key revelations to let them sink in
- **Anticipate objections**: Address "why should I care?" preemptively

### Handling Questions
- Repeat the question for the room
- Acknowledge good questions genuinely
- Use appendix slides for detailed follow-ups
- Say "I'll follow up" for questions outside your analysis scope
- Never guess — commit to finding the answer

## Presentation Anti-Patterns

| Anti-Pattern | Problem | Fix |
|-------------|---------|-----|
| Data dump | Overwhelming, no story | Curate and narrate |
| Chart junk | Distracting decorations | Simplify, maximize data-ink |
| Reading slides aloud | Boring, redundant | Tell the story around the slide |
| No recommendations | Analysis without action | Always end with "so what?" |
| Too many decimal places | False precision | Round to meaningful precision |
| Starting with methodology | Delays the payoff | Start with findings |
